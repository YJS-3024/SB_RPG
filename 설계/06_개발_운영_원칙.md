# 개발 운영 원칙

## AI 활용 방식

이 프로젝트에서는 AI를 단순 코드 생성기가 아니라 설계 리뷰어, 문서화 도우미, 기술 검토자로 활용한다.

큰 구조는 사용자가 직접 고민하고 구현한다.

AI가 주로 맡을 역할:

- 설계 선택지 비교
- 책임 분리 검토
- 클래스 의존성 검토
- 확장성 피드백
- 코드 리뷰
- 리팩토링 제안
- 테스트 시나리오 제안
- 문서화

AI가 바로 완성 코드를 제공하지 않는 영역:

- Player FSM 전체 구조
- Character Loader / Parts Combiner 전체 구조
- Behavior Tree 전체 엔진
- Weapon Combat System 핵심 구조
- Map Generator 핵심 아키텍처

## 권장 작업 흐름

```text
1. 사용자가 구조 초안 작성
↓
2. 클래스 목록과 책임 설명
↓
3. AI 설계 리뷰
↓
4. 사용자가 코드 구현
↓
5. AI 코드 리뷰
↓
6. 리팩토링 방향 정리
```

## 설계 시 체크할 질문

- 이 클래스가 바뀌는 이유는 하나인가?
- 이 객체가 몰라도 되는 정보를 알고 있나?
- 데이터와 실행 로직이 섞였나?
- 새 무기나 상태 추가 시 기존 코드를 많이 고쳐야 하나?
- 런타임 객체와 에디터/데이터 객체가 섞였나?
- 테스트 가능한 구조인가?

## 문서 운영

프로젝트의 핵심 결정은 대화에만 남기지 않고 Markdown 문서로 남긴다.

추천 문서:

- 프로젝트 개요
- 기획 방향
- 기술 설계
- 캐릭터/전투 설계
- 맵/월드 설계
- UI/아트 방향
- 개발 운영 원칙
- 로드맵

문서는 ChatGPT, Codex, 사람이 모두 참고하는 단일 기준으로 사용한다.
