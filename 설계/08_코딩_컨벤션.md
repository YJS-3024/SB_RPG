# 코딩 컨벤션

## 기본 원칙

- 기존 프로젝트의 구조와 이름을 우선한다.
- 한 메서드는 하나의 책임만 가진다.
- 동작이 드러나는 이름을 사용하고 축약어는 피한다.
- 요청 범위를 벗어난 리팩토링은 하지 않는다.

## C# 지역 변수

- 우변만 보고 타입을 쉽게 알 수 있으면 `var`를 사용한다.
- 타입 자체가 중요한 경우에는 명시적 타입을 사용한다.

```csharp
var player = GetComponent<PlayerUnit>();
GameObject skeleton = Instantiate(prefab, transform);
```

## 이름 규칙

- 클래스, 메서드, 프로퍼티: `PascalCase`
- 지역 변수, 매개변수: `camelCase`
- private 필드: `_camelCase`
- 상수: `PascalCase`
- bool 이름: `is`, `has`, `can`, `should`로 시작한다.

## Unity 규칙

- Unity 생명주기 메서드는 필요한 경우에만 사용한다.
- `GetComponent`와 `Resources.Load` 결과는 null을 확인한다.
- 런타임 코드와 Editor 코드는 폴더와 참조를 분리한다.
- Inspector에 노출할 필드만 `public`으로 선언한다.
- 파괴되거나 생성되는 오브젝트는 소유자가 정리 책임을 가진다.

## 코드 형식

- 중괄호는 새 줄에 작성한다.
- 한 줄에는 하나의 문장만 작성한다.
- 매직 넘버와 문자열은 의미 있는 상수로 분리한다.
- 복잡한 로직에만 짧은 주석을 작성한다.
- 파일 인코딩은 기본적으로 UTF-8을 사용한다.

## 검증

- 변경 후 관련 파일의 문법과 참조를 확인한다.
- Unity Console의 컴파일 오류가 없는지 확인한다.
- 동작 변경이 있으면 최소 한 가지 재현 시나리오를 확인한다.
